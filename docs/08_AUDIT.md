## 6. Архитектурные решения фикса (кратко)

- **Матрица переходов** лидов: review→ready/rejected/dnc; ready→contacted/unknown/rejected/dnc; contacted→replied/phone/unknown/dnc; replied→phone/dnc; phone→replied/dnc; unknown→ready(оператор)/rejected/dnc; rejected→dnc; **dnc терминален**.
- **Outcome-контракт**: whitelist `previewed|sent|not_sent|login_required|restricted|target_unavailable|uncertain|failed`; `sent` = только live-lease + точный handle + не-DNC; исходы по истёкшим lease принимаются.
- **Blocklist** — отдельная таблица; opt_out незнакомца не теряется; кандидат с blocklist-хэндла рождается сразу `dnc`.
- **Миграции**: лёгкие, без деструктива (`PRAGMA table_info` + `ALTER ADD COLUMN`), живая БД (`data/insta-ebasher.sqlite`) поднимается без ручных действий.
- **Панель** переписана без вложенных шаблонных строк (стабильнее парсится), все действия по-прежнему только intent → API.
